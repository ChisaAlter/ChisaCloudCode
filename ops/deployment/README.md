# W12 isolated deployment candidate

This source is an offline, reviewable candidate. It has not built, pulled, installed or run any image and has not changed production. Lead must keep G1 and real Docker deployment acceptance blocked until independent proof exists.

`render.py` is used by `../host-hardening/hardening.py`. It deterministically emits Docker Compose JSON, an API Dockerfile, a gateway Dockerfile, a private nginx proxy configuration, candidate and independent signer systemd units, a socket contract and exact UID/HOME mappings. The bundle includes the fixed root signer source and protected shared namespace helper in their stable relative installation layout. Compose JSON is an accepted Compose input format. Missing registry digest values produce an explicit `OPERATOR_DIGEST_REQUIRED` placeholder; `preflight` rejects it before any daemon mutation. Do not substitute a mutable tag or claim an unbuilt image has passed scanning.

The input to `Dockerfile.api` is an already built, inspected **Linux** release tree under `release/`. This includes compiled `dist-server`, built frontend, production dependencies/native binaries and fixed worker assets. The Dockerfile performs no network package install. The release pipeline must pin the base image, lock/SBOM/source hashes, scan the final candidate and rollback digests, inspect default user/entrypoint and run business tests. It must verify no secrets, Docker socket client fallbacks or private enrollment/signing state entered the image. This candidate does not generate that proof itself.

The API uses a fixed non-root numeric UID/GID, cap-drop ALL, no-new-privileges, read-only root, bounded tmpfs/resource/log limits and no host network/PID/socket. It never joins an account network. HOME and WORKSPACES_ROOT retain their historical absolute values; HOME is tmpfs with only the exact persisted runtime state leaf mounted, plus optional individually enrolled read-only provider slots. A full root HOME or host secrets directory is not mounted into workers or API. Exact protected client catalogs and restricted Unix directories are visible to the API; independent broker/issuer/slot authority state is outside it. The external private `/opt/chisacloudcode/secrets/api.env` is consumed by the root launcher as an env file, never copied to a bundle/image or printed. Provider native history paths must be individually registered read-only, with isolated UID/ACL compatibility evidence.

The non-root ingress proxy owns one fixed service-network address. Only it publishes a candidate port on **127.0.0.1** for the existing external reverse proxy to hand off. It strips untrusted forwarding headers, sets the exact Host/proxy contract, preserves HTTP, WS/SSE and streaming upload, and never logs requests/queries/tokens. The API trusts only its exact fixed proxy IP. Existing public proxy/cert/shared ports are preserved by the host candidate. Real proxy chain/client-IP policy, double proxy behavior and readiness must be demonstrated in the acceptance environment.

`egress` is an explicit list of narrow public IPv4 destinations, protocol, port and purpose (`dns`, `provider`, `public-ssh`). Empty egress keeps the service bridge internal and is not sufficient to prove provider/SSH availability. The rendered exact-source DOCKER-USER/INPUT policy permits only API→account gateway, ingress proxy→API, gateway→its one account subnet and operator egress entries, then denies new host/cross-network access. These firewall scripts are render-only; preflight requires independent `candidate_firewall_applied` and `egress_policy` acceptance artifacts. Private SSH targets, dynamic provider/CDN address sets, IPv6 egress or a native nft Docker backend require a reviewed adapter and new isolation tests, never broad private-network exceptions. No candidate firewall command is automatically executed.

## Account preview gateway

`preview-gateway.mjs` is a separate non-root Node24 service using only Node standard library. It joins the service network and **one exact operator-enrolled account network**. There are no host ports, Docker socket, private key, issuer manifest or ticket catalog in its container. The API may reach only the gateway's fixed port. Exact current broker receipt validation pins the upstream immutable container/IP/port; the gateway does not accept arbitrary URLs, names, DNS resolution, metadata addresses, or another account subnet.

Task17 implements the independent root signer, gateway renewal service and runtime consumer. The runtime sends an opaque signed preview ticket only to the fixed catalog's account gateway and retains its browser origin sandbox/basepath/live capability. The public SO_PEERCRED peer front observes real caller birth and forwards exact operation/base selectors to the root-only signer; the signer independently resolves the active broker lease mapping and current immutable broker resource before signing. The API cannot supply the target, gateway, profile, expiry or caller PID. Captured persistent login-session checks revoke local streams first and retry exact independent signer closure, while native cleanup remains a separate obligation. `runtime_gateway_acceptance` remains a mandatory independent deployment gate: implemented source and isolated composition tests do **not** claim that production previews already use or pass the new layout. See the current task17 protocol and evidence under `docs/remediation/2026-10-31/W12-preview-integration`.

Incoming request:

```text
HTTP method /api/workspace-runtime/preview/<64-lowercase-hex-live-capability>/... HTTP/1.1
X-Chisa-Preview-Ticket: <base64url(JSON bytes)>.<base64url(Ed25519 signature)>
```

The exact signed claim fields are:

```json
{"version":1,"audience":"gateway-specific-audience","keyId":"operator-public-key-id","accountId":"one-account","workspaceId":"workspace","generation":"independent-generation","leaseId":"independent-broker-lease","operationId":"exact-operation","resourceId":"64hex-immutable-container-id","host":"172.30.241.10","port":3000,"base":"/api/workspace-runtime/preview/1111111111111111111111111111111111111111111111111111111111111111/","issuedAt":1900000000000,"expiresAt":1900000060000,"brokerProof":"independently-signed-broker-preview-proof","renewalHandle":"256bit-server-side-opaque-handle"}
```

The independent signer issues at most60second tickets and the gateway renews when remaining validity reaches30seconds, using only a server-persisted opaque handle over the separate protected gateway-only renewal Unix socket. Each new request/upgrade verifies account/key/audience/time/path and the restricted broker `/v1/preview`; exact immutable resource/IP/port must still match. Ongoing connections recheck broker authorization every5seconds and can outlive the original ticket when a fresh independent mapping/status/preview proof authorizes the identical resource/lease/account/base. Expired handles, stopped/quiesced leases, changed resources, peer death, signer restart or renewal failure cannot resume old streams. After an idle gap, an exact fresh trusted request may replace an open expired record's handle only after full independent reauthorization/current-resource verification; the old handle remains unusable, and closed records cannot reopen. The gateway receives only a public Ed25519 key, never signs tickets or receives the producer private manifest/key. Private signer `/v1/ticket` and `/v1/close` are root-only; public API preview routes reach them through the trusted peer front. The gateway-only renewal directory is absent from API mounts and uses a separate GID from every API primary/supplemental group.

Application Authorization/Cookie/proxy/origin/forwarding headers and the gateway ticket are stripped before preview upstream. Set-Cookie, Service-Worker-Allowed, active report/policy headers and external redirects are removed/rejected. Same-base redirects and WebSocket frames are preserved. Request budgets, connection counts, idle timeouts and streaming pipe backpressure are bounded. The runtime remains responsible for its origin-bound browser CSP; the gateway adds a restrictive sandbox baseline.

## Native recovery materialization

The offline input now requires a `recovery` domain with exactly the fixed catalog path `/etc/chisa/workspace-broker-recovery.json`, its SHA256, dedicated `client_gid` and `metadata_gid`, fixed native witness directory `/var/lib/chisa-native-stopped`, the private independent authority manifest path/hash, and an optional pinned independent stop-producer verification record. API mounts only the catalog and native witness directory read-only. Their required ownership is root:recovery-read-GID, directory0750/file0640. They are readable to UID10001 without any privilege gain and cannot be edited by it. The gateway receives neither group nor mount; its renewal group is distinct from every API group. The private authority manifest, host stop-witness directory, registries and signing keys remain outside the API.

The exact workspace metadata parent is root:native-metadata-GID mode01770. Only the API belongs to that metadata group; sandbox worker primary/supplemental groups must exclude it. The workspace leaf is owned by an independently enrolled worker/root UID, never the API UID, with fixed device/inode and `rootUid`/`nativeAccountGroupId` in the authority/broker policy. A worker-owned0770 leaf may allow API-primary-group project reads/writes while sticky parent semantics deny API leaf rename/replacement. Native lease/generation/guard siblings remain API-owned private files, so the existing nonroot helper can publish generation CAS without obtaining root capability. Preflight reopens the fixed catalogs, checks exact scope/ticket agreement and root ownership/group/mode/hash, verifies the independent root enrollment and leaf pins, and refuses missing or mismatched producer evidence.

Rendering does not generate operator tickets, enrollments or stop records. The default example has no independent stop-producer evidence and therefore cannot activate. That root supervisor must positively wait/fence the old writer, retain the original host-PID and native-PID birth observations, write atomic durable witnesses, and pass actual nonroot recovery and leaf-swap negative checks. Missing `/proc` PID, an API cleanup boolean or a broker closed receipt alone cannot prove native writer death. This producer and real Docker/G1 acceptance remain explicit independent deployment gates. A complete broker close receipt now requires `resourceInventoryComplete:true`; its full resource list may be empty for a private reservation that never dispatched, while all native stop/guard/CAS checks still apply.
