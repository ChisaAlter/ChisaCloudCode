# 多会话与同步项目执行隔离设计

## 目标

让同一项目中的多个会话按实际写入风险协同运行：

- 本地直连项目保持原生 `cwd` 执行，多个会话可以并行。
- 已开启本地同步的项目不再因为另一个会话正在工作而全局排队。
- 只读会话不占用共享写入锁；需要修改共享主工作区的操作仍按项目根目录串行。
- 写入会话使用独立的 Git worktree（非 Git 目录使用明确的容器/复制隔离策略），完成后保留 worktree，由用户手动合并回主项目。
- 不要求用户关闭本地同步。
- 移除同步必须是原子操作：清理没有得到确认时保留本地映射和远端标记；清理成功后，项目转为可独立运行的 cloud-only/unbound 项目。

## 用户可见语义

1. 新会话根据权限和操作类型选择执行模式。计划/只读模式可以与正在写入的会话并行；写入模式只等待共享主工作区或合并操作。
2. 独立 worktree 的结果不会自动覆盖主项目。会话结束后 worktree 仍然可见，用户从 Worktrees 入口检查差异并手动合并。
   Worktree 保留会话完成时的未提交改动；在 Worktrees 的合并动作前先在该 worktree 检查并提交，避免把未经审阅的文件覆盖主项目。
3. 解绑失败不会留下“半解绑”项目。界面继续显示同步受阻，并提供恢复同步/重试；解绑成功后同步标记消失，项目可像普通云端项目一样继续创建会话、读写文件。

## 约束与边界

- 不能通过简单删除租约、修改租约键或隐藏排队来伪造隔离。
- 共享写入、同步回写和手动合并仍须经过项目级互斥。
- 非 Git 同步目录暂不假设存在可安全合并的 worktree；必须使用真实的容器/复制隔离，否则保持写入排队并显式说明原因。
- 旧的本地直连入口、项目路径、会话数据和同步状态字段保持兼容。

## 验收证据

- 同一同步根目录上，一个写入会话持有共享锁时，另一个只读会话可以执行并获得结果。
- 两个写入会话不会写入同一个根目录；每个会话的 worktree/container 标识独立，完成后可在 Worktrees 入口手动合并。
- 移除同步在清理失败时保留映射和标记；清理成功后 `GetProjectSync` 返回 `unbound`，项目继续走 cloud-only 执行路径。
- 本地直连项目的原有多会话并行路径和现有同步恢复路径不回归。
- 自动化检查通过后，再用构建出的客户端验证截图所示的实际发送、解绑和第二会话路径；没有安装包/运行实例证据时不得声称 UI 验收通过。
