# SSH 本地项目开发

ChisaCloudCode 支持按项目选择云端 VPS 或 SSH 本地开发。已有项目默认仍是云端项目，登录、模型连接、文件、Git、终端、会话隔离和改动集成保持原有路径。选择 SSH 本地时，Claude Code、认证和会话记录继续在 VPS，文件、Git 和 Windows 命令在选定电脑上执行。

## 使用前提

- VPS 应用服务可以执行 OpenSSH 客户端，并可以连接受限 SSH 端点。
- Windows 已安装并运行 OpenSSH Server；执行账户是有项目与必要工具链权限的普通账户。
- Windows 的系统 PowerShell 5.1+、Git 和项目自己的编译运行工具可用。不需要 Windows 上的 Claude Code、Node 服务或 MCP 服务。
- 两端均配置密钥认证并固定主机指纹。私钥不存放在项目目录，不经聊天、前端或日志传递。

应用不自动安装 SSH 系统服务、创建 Windows 账户或放宽防火墙。反向隧道只需要 Windows 回环端点，不需要向公网开放笔记本端口。

## 连接路径

```text
桌面 ──现有 HTTPS/WS──> VPS 应用 + Claude Code
                           │
                      SSH 传输适配器
                           │
                       Windows sshd
                           │
                  Windows 项目和工具链
```

笔记本无法被 VPS 直接访问时，在“设置 → Chisa → SSH 本地开发”保存并启动反向隧道：

```text
Windows ssh.exe -R 127.0.0.1:<VPS端口>:127.0.0.1:<Windows SSH端口> → VPS sshd
VPS 应用 ssh → 上述回环端口 → Windows sshd
```

这是两个独立的 SSH 认证角色：Windows 持有外层隧道密钥，VPS 持有登录 Windows 的执行密钥。外层转发成功只证明反向端口建立；项目创建时还会验证内层登录、Windows 辅助脚本和真实目录。

如果应用服务运行在容器中，VPS sshd 的回环地址不等于应用容器的回环地址。部署时将受限转发端点与适配器放在同一个账号网络空间，或提供明确的私有账号通道。不要通过公开绑定端口来绕过此问题。

## Windows 辅助脚本

桌面 SSH 设置提供“安装辅助脚本”，将安装包内协议 1 的脚本复制到本机应用数据目录，并显示完整路径和摘要。辅助脚本通过 SSH 按需运行，经 stdin 接收结构化请求、stdout 返回单个 JSON，不启动常驻服务。

将其放在项目外，确认专用 SSH 账户有读取权限；若默认用户数据目录不可读，管理员可将同一脚本部署到受保护的共享安装位置，再将实际路径登记到 VPS。安装动作不声称自动配置专用账户 ACL。

## VPS 连接目录

服务端通过 `CHISA_SSH_CONNECTIONS_FILE` 指向管理员维护的 JSON。示例字段：

```json
{
  "connections": [
    {
      "id": "my-windows",
      "name": "我的 Windows 电脑",
      "ownerId": "1",
      "host": "127.0.0.1",
      "port": 22022,
      "username": "cc-worker",
      "identityFile": "/srv/chisa/secrets/windows-execution-key",
      "knownHostsFile": "/srv/chisa/secrets/windows-known-hosts",
      "hostKeyAlias": "chisa-device-my-windows",
      "helperPath": "C:\\ChisaTools\\ssh-workspace.ps1"
    }
  ]
}
```

`ownerId` 是应用认证账号 ID，不是 Windows 用户名。登记文件和密钥应由服务端账户持有，避免组/其他用户可写。服务端只向已认证用户列出安全连接信息，不返回密钥文件路径或私钥内容。配置变更按请求读取，无需将密钥交给 CC。

共享连接 `ownerId: "*"` 只在非平台部署且显式配置 `CHISA_SSH_ALLOW_SHARED_CONNECTIONS=1` 时启用。多人环境应使用独立 owner、密钥、端口和 Windows 账户。

外层 VPS 转发账户应限制远程端口转发、指定回环端口，并禁用不需要的 shell/PTY/代理转发；内层 Windows 主机指纹用稳定设备别名校验，不能因回环端口复用而自动信任另一台电脑。SSH 设置中的远端端口必须和服务器登记目录一致。

## 打开项目

1. 正常登录云端账号。
2. 需要反向隧道时，在桌面 SSH 设置检查前提、保存配置并启动。应用不会因云端登录而自动启用 SSH。
3. 新建项目选择“SSH 本地”，选择服务端已登记连接，填写或选择 Windows 现有项目目录。
4. 点击连接检测。成功后才可确认创建；服务端创建时再次核实真实 Windows 身份和物理目录。
5. 项目顶部显示“Claude：VPS，文件/Git/命令：Windows”。文件树、编辑器、Git、聊天与 Windows 命令控制台使用同一个目标。

源码不整体复制到 VPS。应用在 VPS 保存独立会话元数据锚点，不能将该目录当作源码读取或编译。删除/归档应用项目记录不会删除 Windows 项目目录。按需读取的源码、补丁和日志会经过 VPS 并进入会话；该模式不承诺源码零外传。

## 当前能力与边界

- SSH 项目支持 Claude 聊天、目录/文件读取、带内容哈希的写入、搜索、文件管理、基础 Git、构建与测试命令。`@` 文件引用使用项目路径；截图可用图片工具视觉读取，显示图片时采用相对路径或 `/workspace/...`。非图片上传附件通过限定到当前消息附件的只读工具访问，不能借此读取任意 VPS 文件。
- Windows 命令控制台每行是独立 PowerShell 任务，起始目录固定为项目目录，不保留上一行的变量或 `cd` 状态；不支持交互式输入、全屏程序或终端 resize。需要连续命令时写在同一行或运行项目脚本。
- 计划/只读会话只允许读取文件，不能运行任意命令；SSH 没有云端只读容器挂载保证。
- 本地目录共享，应用内部串行写入任务。相同账号不能通过其他连接别名重复登记相同卷/文件身份；当前采用保守去重，克隆磁盘或虚拟机罕见身份碰撞会被拒绝，需要使用不同物理目录。编辑器保存检查上次读取哈希，外部 IDE 的已知变更会报告冲突；构建与外部 Git 操作仍会共享工作状态。
- Windows 的实际文件访问权限由 SSH 登录账户与 NTFS ACL 决定，工作目录不是进程沙箱。
- 本地会话隔离 worktree、会话改动集成、云端预览代理、桌面 UI 自动化和其他提供商暂不可用；这些能力在云端项目保持原行为。
- 不恢复 Mutagen、旧同步接口或本地 Pi。旧同步记录继续只用于原有迁移与退休检查。

## 断线与恢复

应用只管理自己启动的 SSH 进程，退出、登出或切换账号时停止自己的隧道，不关闭系统 sshd，也不杀其他 SSH 连接。重启后保存的配置保持停止，可显式重新连接。

SSH 失败不会回退到 VPS 文件或命令。写入命令不自动重放；远端任务有独立 ID，在请求发出前写入服务端恢复记录。取消/超时尝试停止对应 Windows Job Object 并核实结束；无法确认时保留恢复屏障，在项目顶部检查原任务或停止原任务后恢复。

服务进程重启后，残留的运行身份以“等待恢复”显示。没有命令回执的任务只可能处于文件操作阶段，恢复不会重复执行文件修改，提示用户检查上次改动。命令存在回执时只对那个任务查询/取消，不将 SSH 连接断开视为进程已退出。

Windows Job Objects 用于正常进程树的生命周期与资源控制，不作为恶意构建脚本的文件或网络安全沙箱。
