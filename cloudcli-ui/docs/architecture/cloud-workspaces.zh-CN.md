# 云端项目与会话工作区

ChisaCloudCode 默认使用云端开发。云端项目的文件、Git、终端、AI 执行和网页预览都由云端服务负责；桌面应用负责账号连接和界面，不创建源码镜像或进行实时同步。按项目新增的 [SSH 本地模式](ssh-local-workspaces.zh-CN.md) 将文件与命令放在 Windows，Claude Code 和认证继续在 VPS；本文说明云端模式。

## 开始使用

1. 连接并登录云端账号服务。
2. 在新建项目中选择服务器目录，或将 Git 仓库克隆到服务器目录。
3. 在项目内使用聊天、文件、Git 和终端。需要隔离执行的会话使用独立的云端会话工作区，完成后可预览并集成改动。

项目不再要求绑定 Windows 文件夹、配置文件同步 SSH 密钥、安装 Mutagen 或等待本地同步收敛。关闭桌面应用不会停止由云端管理的运行环境。

## 目录与执行身份

云端项目主目录是持久项目入口。支持隔离的 Git 仓库可以为会话保留独立目录和初始基线；不支持隔离的目录会显示实际共享执行模式。文件、Git、终端、聊天与命令均使用服务端解析的工作区身份和代际，身份变化后必须重新解析。

云端使用账号拥有的运行网络。新项目由服务端创建云端身份与持久写入协调状态，不再向桌面发送同步开始、同步完成或本地 Git 请求。并发写入、未完成集成及无法确认的进程清理仍会阻止新的写入操作。

## 会话改动集成

隔离会话的改动可以先预览，再集成到云端主工作区。集成只应用会话相对初始基线的文件差异，并保留目标 HEAD 和暂存区；用户决定何时暂存与提交。

同一文本互不重叠的修改可三方合并。重叠修改、二进制冲突、删除与修改冲突及受保护路径会报告冲突。响应中断时重试原集成操作或检查恢复，不创建新的重复操作。尚未确认完成的集成会保留写入屏障。

## 旧同步项目

升级不会删除本机或服务器上的项目文件，也不会把本机尚未上传的内容自动合并到云端。

桌面启动时只检查属于当前配置且端点身份匹配的旧同步会话，并暂停它们；不会启动新的同步守护进程。云端恢复账号运行环境时检查原同步容器的所有权、挂载与不可变容器 ID，取消自动重启并停止该容器，保留容器及项目数据。新的文件同步登记接口已移除。

旧项目只有在云端版本完整、没有未完成租约或集成时才会接管为云端项目。接管保留原绑定代际，避免使已经保留的会话与基线失效。状态不完整时应先核对云端文件并恢复具体未完成操作；服务不会删除状态文件来绕过屏障。

## 部署与验证边界

受隔离的云端执行需要 Linux、Git、Python 3、Docker、独立的 `WORKSPACES_ROOT` 和 `localhost/chisa-workspace:3` 运行镜像。账号运行网络由服务端建立，无需同步 sidecar 或同步引擎镜像。普通自托管服务器仍可通过浏览器提供服务。

预览由云端容器和令牌路径代理管理；项目应用需支持 `CHISA_PREVIEW_BASE` 路径前缀。VPS 终端当前为容器管道，不是完整 PTY，仍保留既有交互边界。

源码修改、自动化回归与本机构建不等于生产 VPS 或桌面安装包已更新。部署服务器和发布安装包是独立步骤。
