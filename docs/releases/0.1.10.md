# ChisaCloudCode 0.1.10

This release brings the Windows desktop, Web interface and Linux server to one source revision. Update the desktop and server together; keep the previous installation and server image available until the updated deployment has passed its checks.

## Synchronization and Git recovery

- Healthy message handoffs reuse the active synchronization watcher, Git observations and ignore-policy evidence. They no longer replace the observer just because preparation and handback have different recovery permissions.
- A first synchronization with divergent branches and no Git baseline offers an explicit recovery preview. The preview reports both endpoints and rejects unsafe receiving-side staged or in-progress Git state. Confirmation is short-lived, single-use, and bound to the exact connection, project, session, lease and observed state.
- A durable pending plan is saved before recovery writes. Reconnection can resume the same plan; changed state requires a new preview. Existing branch references, portable index stages and operation metadata are preserved.
- Preview index/tree calculations use private Git metadata and object storage. Split-index, sparse-index and linked-worktree previews avoid mutating the source repository.
- Ignore updates retain the synchronization archive. Normal handoffs do not unconditionally pause/resume the engine or enumerate the full project; changes to Git state, policy or trustworthy observations still require verification.
- HTTP requests retain TLS validation and connection reuse. Cancellation is scoped to the request owner; completed POST operations are not replayed after a transport error.

## Workspace and conversation behavior

- Native Git reads and branch operations are bound to the current workspace and hold the appropriate ownership boundary. Git panel history refreshes, stale responses and operation errors are handled explicitly.
- Shared and isolated Claude sessions retain their workspace mode. Isolated startup snapshots project state into a session worktree while protecting source ownership; shared mutations remain serialized through exact leases.
- Task completion waits for the real child process and cleanup/handback. Interrupted cleanup retains recoverable state rather than showing success early.
- Queued messages retain their content and options until successful execution. Per-session dispatch avoids blocking unrelated conversations and handles retryable workspace admission without losing queued input.
- Channel replay epochs, account-switch barriers, process termination checks and one-submit desktop login from the existing public codebase remain in place.

## Desktop and server packaging

- MyGo is the Windows desktop host. The former Electron packaging entry points are removed.
- Desktop, frontend and server report their version and source commit. Linux container builds accept the full source commit and record it in the build identity and image labels.
- The Linux server archive contains Web/server code, runtime resources and a lockfile. Install its production dependencies using Node.js 24 on Linux; Windows native modules are not interchangeable with Linux modules.
- The required synchronization engine is **0.18.1-chisa.2**, with Windows amd64 CLI and Linux amd64 agent. Runtime files, checksums, complete patched source and upstream notices accompany the release. Rebuild instructions and a cumulative patch are in `ops/mutagen/`.
- Existing public dependency security upgrades are retained; Claude Agent SDK is pinned to 0.3.303.

## Upgrade notes

Back up the server database, conversation data and deployment configuration. Wait for active tasks to finish before replacing the server container or desktop process. Keep persistent mounts and credentials outside the source tree.

An upgrade does not resolve existing merge or cherry-pick conflicts, choose a Git recovery direction automatically, or publish your project repositories. Review any recovery preview and preserve both endpoints before selecting a source.

Initial enrollment, cold startup, observer retirement after an idle period and genuine project changes may require fresh verification. Stable warm handoff measurements are not a guarantee for large directory additions or concurrent Git work.

The Windows installer is unsigned. This release provides Windows amd64 desktop and Linux amd64 server/runtime support; other platforms have not been validated for these artifacts.
