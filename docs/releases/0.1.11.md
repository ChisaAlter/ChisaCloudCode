# ChisaCloudCode 0.1.11

This is the published synchronization/Git recovery update for the Windows desktop, Web interface and Linux server. It includes the [0.1.10 source changes](0.1.10.md) and the corrections found during installed-application acceptance. The 0.1.10 source tag remains available; its release candidate was withdrawn before publication.

## Account transport

The HTTP/1 account client now creates a fresh verified TLS configuration with or without a distribution CA. Go initializes HTTP/2 on the default transport before cloning it; an inherited ALPN list could otherwise negotiate HTTP/2 even though the account client selected only HTTP/1. Existing login tokens can again restore the account through the public system-trust configuration. TLS validation, connection reuse, cancellation and the non-replay boundary remain in place.

## Isolated workspaces

The API may run as root while synchronized repositories belong to the workspace user. Session-worktree Git operations now use that repository's execution identity, with disabled hooks/filesystem-monitor commands and an isolated Git configuration. New worktree directories, snapshots and bridge metadata are writable by the same workspace user; source repository ownership and index state are preserved.

Repository-reading failures are reported before starting the model instead of being treated as evidence that Git is unavailable. This prevents a Git ownership error from silently starting an isolated session on the shared repository.

## Upgrade and validation

Update the desktop and server together. Back up the account database, conversation data and deployment configuration, let running tasks finish, and retain the previous image and installation for rollback. Persistent mounts, credentials and project repositories stay outside release artifacts.

The release combines frontend/backend suites with native transport and synchronization tests. Installed-application acceptance checks automatic login restoration, authenticated requests, two shared turns and a separate isolated worktree turn. The isolated check includes the actual on-disk worktree and its workspace-user write permissions, rather than relying on the session's mode field alone. Initial failed and timed-out test runs and their corrective reruns are described in the published verification record.

The Windows installer is unsigned. These artifacts target Windows amd64 and Linux amd64. Cold enrollment, large file changes and Git recovery still need more work than unchanged warm message handoffs; small-project timing measurements are not a general latency guarantee.
